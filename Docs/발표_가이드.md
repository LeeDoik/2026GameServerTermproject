# 텀프로젝트 발표 가이드 — Aetheria Online

발표 구조: **5분 발표 + 5분 시연 + 5분 질의응답**

---

## 핵심 전략

> **발표(슬라이드)는 "서버 엔지니어링"으로 채우고, 게임 기능은 영상으로 넘긴다.**

이 과목 채점관(교수)이 가장 보고 싶어 하는 건 ① 실습코드 안 쓰고 IOCP·패킷조립·타이머·DB·스크립트를 **직접** 만들었는가(–20% 페널티 항목), ② **성능/동접**이다. 게임 콘텐츠(파티·퀘스트·보스 등)는 점수는 크지만 "영상으로 보여주면 충분"한 영역이라, 짧은 5분 발표를 콘텐츠 나열로 낭비하면 손해다.

**말로 해야 설득되는 것**(아키텍처·최적화 여정·자체구현)을 발표에 넣고, **눈으로 봐야 믿는 것**(기능 동작)을 영상에 넣는다.

---

## 1) 5분 발표 (슬라이드) — 6장 구성

| # | 슬라이드 | 시간 | 핵심 메시지 |
|---|---------|------|------------|
| 1 | **타이틀 + 성과 한 줄** | 0:00–0:30 | "Aetheria Online — Win32 IOCP MMORPG. **20만 NPC / 단일 머신 3,462 CCU @ 0~1ms / 핵심 서버 모듈 전부 자체 구현**" 이 세 숫자를 먼저 박고 시작 |
| 2 | **통합 IOCP 아키텍처** | 0:30–1:15 | 보고서 3장 다이어그램. "네트워크 I/O·타이머 만기·DB 완료를 **하나의 IOCP**로 통합 → 모든 게임 상태 변경이 워커 컨텍스트에서만 발생 → 동기화 규약 단일화" |
| 3 | **20만 NPC를 버티는 3대 비결** | 1:15–2:15 | ① 섹터 기반 AOI(9섹터만 검사) ② **Lazy AI**(플레이어 근처 NPC만 활성, 활성 수 = 동접 비례) ③ **워커 로컬 Lua VM**(thread_local, AI 핫패스 락 0) |
| 4 | **최적화 여정 (스토리)** | 2:15–3:15 | "**3,000 CCU 벽** → 원인 진단(단일 Lua락·단일 타이머·전역 송신풀) → Phase1 병렬화(워커VM·8샤드 타이머·8샤드 송신풀) + Phase2A 송신 코얼레싱 → **3,462 @ 0~1ms로 벽 해소**". 화살표 전후 비교로 보여주면 임팩트 큼 |
| 5 | **자체 구현 (표절 방지 정면돌파)** | 3:15–4:00 | "제공된 `protocol_2026.h`만 사용. IOCP 래퍼 / 패킷조립(Length-Prefix + 자체 **RingBuffer**) / 타이머(**Min-Heap**) / DB 비동기 Job Queue / Lua 바인딩 — **전부 scratch부터**." → –20% 페널티 항목을 발표에서 먼저 못 박아 질문을 차단 |
| 6 | **게임 콘텐츠 한눈에 + 채점 매핑** | 4:00–5:00 | 4바이옴·스킬3종·파티·아이템/장비·연쇄퀘스트·2페이즈 보스를 **아이콘+한 줄씩** 한 장에. "동작은 곧 시연 영상으로 보여드리겠습니다"로 자연스럽게 시연으로 전환 |

**발표 팁:** 5분은 정말 짧다(슬라이드당 ~50초). **슬라이드를 읽지 말고** 위 "핵심 메시지"만 말로 풀고, 숫자(3,462 / 0~1ms / 20만)는 반드시 입으로 강조한다.

## 2) 5분 시연 — 영상 구성 (편집된 한 편 권장)

기능별로 따로 찍되 **하나의 영상으로 편집 + 자막 오버레이**를 강력 추천. 라이브 시연은 크래시·타이밍 리스크가 있고, 5분 안에 11개 기능을 라이브로 못 돈다. 각 클립 상단에 **`[기능명 — 채점항목]`** 자막을 띄우면 채점관이 항목을 바로 체크할 수 있다.

### 필수(구현 50% 직접 증명) — 앞쪽 배치
1. 로그인 → 이동 → **장애물 충돌** → 시야 객체 출현/소멸 (~35s)
2. **A키 4방향 전투** + 화면 하단 전투 메시지 + **채팅** + 레벨업 (~35s)
3. 몬스터 AI: **Peace vs Agro**(11×11 진입 시 추격), **로밍**, **A\* 장애물 우회**, 처치 후 **30초 부활** (~40s)
4. 플레이어 **사망 → EXP 50% 감소 + 시작 마을 부활** (~20s)

### 게임성(40% 가산) — 중반
5. 스킬 3종: AoE / Line / Heal (~25s)
6. 아이템: 드롭 → G키 줍기 → 장착(스탯 변화) → 인벤토리 (~25s)
7. 퀘스트: 장로 대화(!/? 표시) → 처치 카운트 → 보상 → 연쇄 진행 (~30s)
8. 파티: 클라 2개로 초대 → 수락 → **경험치 공유** (~25s)
9. 보스: 도발 채팅 → HP 50% **분노 페이즈** → 광역기 (~25s)

### 증명용 클라이맥스 — 마지막 2개
10. **DB 영속화**: 캐릭터 종료 → 재접속 시 위치·레벨·인벤·퀘스트 복원 (~20s) ← DB 점수의 결정적 증거
11. **동접 측정**: 헤드리스 부하 클라로 CCU 올라가는 화면 + 서버 `delay=0~1ms` 로그 (~35s) ← 성능 20%의 머니샷, **반드시 맨 끝**에 배치해 강하게 마무리

> 합이 5분에 빠듯하면 5~9번(게임성)은 더 짧게 쳐내고, **1~4 + 10 + 11**(구현+DB+성능)은 절대 줄이지 않는다. 그게 점수 배점이 큰 핵심이다.

**녹화 팁:** 서버 콘솔 로그를 화면 한쪽에 같이 띄우면 전투 메시지·DB Load/Save·CCU delay가 함께 잡혀 "서버가 실제로 처리 중"임이 보인다. 지루한 구간은 1.5~2배속 + 자막.

## 3) 5분 질의응답 — 예상 질문 & 답변

가장 나올 법한 순서로:

- **"IOCP·패킷조립 정말 직접 짰나? 실습코드 안 썼나?"**
  → "네. 고정 헤더 방식이 아니라 가변 길이(Length-Prefix)를 세션별 RingBuffer로 직접 조립합니다. `OVERLAPPED_EX`/`TimerOverlapped`/`DbOverlapped`를 같은 레이아웃으로 설계해 IO_TYPE만 보고 분기합니다." (코드 한 화면 미리 띄울 준비)

- **"5,000 CCU 못 채운 거 아닌가?"**
  → 정직하게: "localhost 3,462는 **서버 한계가 아니라 단일 머신에서 서버+20만 NPC+부하 클라가 CPU를 경합한 환경 제약**입니다. 서버/클라 분리 측정 시 여유가 있다고 봅니다. 분리 머신 5,000 정식 측정은 남은 과제로 보고서 13장에 명시했습니다."
  → 교수가 직접 다른 PC로 테스트할 수 있으니 **서버 exe + 헤드리스 클라(stdin IP 입력)를 즉시 제공 가능**하게 준비

- **"20만 NPC를 다 돌리나?"** → Lazy AI: 평소 비활성, 플레이어 시야 진입 시 CAS로 활성, 시야 비면 자가 비활성. 활성 AI = 동접 비례.

- **"Lua가 락 병목 아닌가?"** → 워커마다 thread_local VM, `OnTick(ctx)`가 stateless라 어느 VM에서 돌든 동일. AI 핫패스 락 0.

- **"DB가 게임 루프를 막지 않나?"** → 비동기 Job Queue + 단일 DB 스레드 + `PostQueuedCompletionStatus(IO_DB_DONE)` 완료 통지.

- **"막타·EXP 중복 안 나나?"** → per-NPC view_lock + CAS로 HP를 0으로 만든 호출만 사망처리 1회.

## 참고: 발표 전 사소한 정합성 한 가지

`direction` 컬럼이 실제 스키마/코드엔 있는데, **보고서 9.3장 `players` 테이블 컬럼 표에는 `direction`이 빠져** 있다. 질의응답에서 스키마를 들이밀 경우 대비해 보고서 표에 `direction` 한 줄 추가해두면 깔끔하다.
