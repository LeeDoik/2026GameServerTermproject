- **라이선스**: CC0 (Creative Commons Zero, public domain 등가) — 자유 사용/수정/재배포 가능, 크레딧 권장
- **크레딧**: `Resource/Dungeon Crawl Stone Soup Full/README.txt` 의 아티스트 명단을 발표 자료/설명서에 포함
- **타일 사양**: 모든 타일 **32×32 PNG** (RGBA 또는 colormap), 투명 배경 (장식/캐릭터) 또는 불투명 (floor)

## 3. 게임 컨셉 재정의 (4대 바이옴 + 시작 마을)

기획서 §2.1 "평원(중앙) / 숲(북) / 사막(동) / 설원(서)"을 코드의 4분할(NW/SW/NE/SE)에 매핑.

### 3.1 월드 구획 (2000×2000)

```
   x=0 ─────────────── x=1000 ─────────────── x=2000
y=0  ┌─────── 설원 (NW) ────┬──── 사막 (NE) ───────┐
     │  얼음 동굴 / 다크캐슬│  피라미드 / 미라    │
     │   서리 거인          │  황금 드래곤        │
y=500│   Lv 30~40           │  Lv 20~30           │
     │                      │                     │
     │     ┌─── 마을 ───┐                         │
y=1000├────┤ 960~1040  ├─────────────────────────┤
     │    │  Aetheria  │                         │
     │    │  Village   │                         │
     │    └────────────┘                         │
     │  초원 (SW)            │  숲 (SE)           │
     │  슬라임/늑대          │  스프리간/하이드라  │
y=1500│  Lv 1~10             │  Lv 10~20          │
     │                      │                     │
y=2000└──────────────────────┴─────────────────────┘
```

| 지역 | 좌표 | 컨셉 | 권장 Lv | 시각 |
|---|---|---|---|---|
| **마을 (중앙)** | (960..1040, 960..1040) 80×80 | Aetheria Village — 안전지대, 시작점, 상점 | — | 베이지 cobblestone |
| **SW 초원** | (0..1000, 1000..2000) | 푸른 평원, 시작 사냥터 | 1~10 | grass + dirt |
| **SE 숲** | (1000..2000, 1000..2000) | 어두운 마법의 숲 | 10~20 | bog_green + trees |
| **NE 사막** | (1000..2000, 0..1000) | 잊혀진 사막, 피라미드 | 20~30 | sand_rock + sandstone |
| **NW 설원** | (0..1000, 0..1000) | 얼어붙은 황무지 | 30~40 | frozen + crystal |

> **주의**: 현재 코드(`MMOSERVER_Termproject.cpp:842`)의 `region_row` 계산은 NW=0, SW=1, NE=2, SE=3 순. 이 매핑을 그대로 유지하되 각 row의 타일/장식만 새 컨셉으로 교체.

- `500+`: 보스/유니크

## 9. 클라이언트 통합 작업 항목 (코드 변경 리스트)

리소스를 게임에 실제로 적용하려면 클라 코드(`CLIENT/client_sample/client.cpp`) 변경이 필요. 우선순위 순:

### 9.1 [필수] 타일 크기 32×32 정수배 통일

- 현재: `TILE_WIDTH = 65` (64px 타일 + 1px 여유)
- 변경: `TILE_WIDTH = 64` (32×32 원본 × 2배 스케일) — 갭/겹침은 SFML 텍스처 setSmooth(false) + 정수 좌표로 해결
- 영향: `WINDOW_WIDTH/HEIGHT`, 이펙트 offset, HUD 위치 등 약간의 픽셀 재계산

### 9.2 [필수] dungeon-tiles-256x256.png 교체

- 옵션 A: 4지역 × 4 variant를 256×256 (또는 256×128) 새 시트로 합성 (DCSS 32×32 타일 16개를 한 시트에 모음)
- 옵션 B: DCSS 원본 32×32 PNG들을 그대로 사용. 클라가 region/variant마다 다른 텍스처 객체 로드 + cache (코드 변경 더 큼)
- **추천**: 옵션 A. Python 스크립트로 한 번 합성 (또는 수동) → 기존 코드 1줄 변경(파일명 + 행 매핑)

### 9.3 [필수] obstacle 시트 교체

- 현재: 흰 sf::RectangleShape
- 변경: 256×64 시트 (4지역×1열) 또는 지역별 32×32 텍스처 4종 → `g_wall_shape` 대신 sprite 사용
- 코드: `client_is_blocked(x,y) == true`일 때 `region_row`에 따라 다른 sprite

### 9.4 [필수] 마을 광장 시각 강화

- 현재: 베이지 반투명 + sf::CircleShape 분수
- 변경:
  - 마을 바닥: `cobble_blood_*` 또는 `floor/marble_*` 시트로 교체
  - 분수: `dungeon/sparkling_fountain.png` sprite (애니메이션 2프레임 가능)
  - 입구: `dungeon/doors/gate_open_*.png` × 3 (좌/중/우)
  - 동상: `dungeon/statues/statue_angel.png`

### 9.5 [선택] visual_id → DCSS 파일 매핑 시스템

- 신규 `data/npc_visual.txt` 로드 → `std::unordered_map<int, sf::Texture*>` 캐시
- NPC OBJECT 그릴 때 visual_id로 sprite 변경
- 서버 코드 변경 없음 (이미 visual_id 패킷에 포함)

### 9.6 [선택] 플레이어 직업 시각화

- LOGIN 시 직업 선택 (현재는 미구현 — 모두 hero-walk 시트)
- DCSS player/base/ 시트 사용
- 향후 장비 레이어 합성 (Stage 7)

### 9.7 [선택] DCSS 이펙트 적용

- `effect/cloud_fire_*.png` 같은 시트를 기존 `spawn_effect_*` 함수에 추가
- 스킬별 다른 이펙트 (Stage 7 스킬 시스템과 함께)

- **파일 경로**: `Resource/Dungeon Crawl Stone Soup Full/`에 공백 포함 — Windows에서는 OK, 빌드 도구 셸 명령 시 쌍따옴표 필수
- **메모리**: 200K NPC × 32×32 텍스처 캐시 → 8KB × 100종(매핑된 visual_id 종류) ≈ 800KB. 무시 가능
- **렌더 성능**: 시야 16×16 = 256 sprite + 동시 가시 NPC ~50 → SFML draw call ~300/프레임. 60FPS 충분
- **표절 영향**: DCSS 타일은 CC0 (public domain 등가). 학기 과제 채점에 영향 없음. 발표 자료에 출처 명기
