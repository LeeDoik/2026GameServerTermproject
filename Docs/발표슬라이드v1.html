02 · NPC

NPC 구현 — 20만 마리 + Lua AI

저장

raw 배열 20만

unique_ptr<NPC[]> 선할당. id = NPC_ID_START+index. shared_ptr 대신 raw로 메모리 풋프린트 최소화.

AI 위임

Lua OnTick(ctx)

판단은 npc_ai.lua가, 적용은 C++가. ctx로 상태 전달 → dx·dy·target_id 반환하는 stateless 설계.

병렬화

워커 로컬 VM

워커마다 thread_local Lua VM. VM 수 = 코어 수(NPC 무관). AI 핫패스 락 0.

평소 비활성
active=false, 타이머 없음
→
시야에 플레이어 진입
CAS(false→true) 1회 성공자만
→
NpcMove 타이머 등록
0.5초마다 OnTick
→
시야 비움 / 사망
active=false 자가 정지
행동: Agro 11×11(±5) 추격 · 로밍 20×20(±10) · A* 장애물 우회 · 사망 후 30초 부활 · 보스 HP50% 2페이즈 분노. → 활성 AI = 동접 비례.
03 · Sector AOI

섹터 기반 시야 — 9섹터만 검사

공간 분할

2000×2000 → 1만 섹터

SECTOR_SIZE=20 → 100×100 = 10,000개 (g_sectors[100][100]). 각 섹터 = 전용 mutex + players/npcs 집합.

갱신

섹터 변경 시에만 이동

UpdateObjectSector: 섹터가 바뀐 경우에만 old 제거 / new 삽입. 섹터별 락으로 전역 락 경합 제거.

시야 검사

내 섹터 + 인접 8

시야(±15) ≤ 섹터(20)라 9섹터가 시야 커버. 후보를 9섹터로 한정 → O(전체) → O(주변).

04 · Persistence

DB 영속화 — 비동기 Job Queue

🚦
게임 루프 비차단게임 스레드는 EnqueueLoad / EnqueueSave 만 호출하고 즉시 복귀. DB I/O로 워커가 절대 블록되지 않음.
🧵
단일 DB 워커 스레드 + IOCP 완료 통지큐를 폴링 → 동기 SQL 실행 → PostQueuedCompletionStatus(IO_DB_DONE) → 워커가 OnDbResponse로 결과 적용.
🔌
백엔드 추상화 (IDbBackend)MySQL ODBC 실연동 + JSON 파일 폴백. db.ini enabled=1 로 전환. 정규화 3테이블(players · 인벤/장비 · 퀘스트).
💾
영속화 범위로그인 시 username으로 Load, 로그아웃 + 주기 AutoSave 시 Save → 위치 · 레벨 · 인벤토리 · 퀘스트 복원.
